// 01 — TOOL

CLI — Command-Line Interface

The Command-Line Interface is a text-based method of interacting with a computer's operating system by typing commands directly. Instead of clicking icons, you type instructions and receive text output in return. It's the foundation of nearly everything a security professional does.

// CLI vs. GUI

A Graphical User Interface (GUI) lets you interact with visual elements — windows, buttons, and menus. A CLI removes all of that and communicates directly with the OS through text. GUIs are easier for casual users, but GUI applications only expose the features developers decided to show. The CLI exposes everything. For a security tester, that total control matters.

// Why Security Professionals Live in the Terminal

Speed: Experienced users execute complex operations in seconds that would take minutes clicking through menus.

Precision: Commands are exact. There's no ambiguity about what you're doing — unlike GUI apps that hide implementation details.

Scripting: CLI commands can be chained and automated. Repetitive tasks like scanning subnets or parsing output are only practical from the terminal.

Remote Access: SSH sessions are terminal-only. When connected to a remote machine, there's often no GUI at all.

// Real Lab Commands

# Navigate to the /etc directory — where system config files live cd /etc # List all files, including hidden ones, with detailed permissions ls -la # Sample output: drwxr-xr-x 2 root root 4096 Jan 10 08:12 ssh -rw-r--r-- 1 root root 3028 Jan 10 08:12 passwd -rw------- 1 root root 1420 Jan 10 08:12 shadow # /etc/passwd lists all users. /etc/shadow stores password hashes. # During a pentest, finding a readable shadow file is a critical finding.

The ls -la flags break down as: -l (long format — shows permissions, owner, size) and -a (show all hidden files that begin with a dot). Understanding file permissions from the terminal tells a tester instantly whether sensitive files are exposed to the wrong users.

SSH — Secure Shell

SSH (Secure Shell) is a cryptographic network protocol that lets you operate a remote computer's command line over an encrypted connection — as if you were sitting in front of it. Before SSH, tools like Telnet sent all traffic, including passwords, in plain text. Anyone with a packet sniffer could read it. SSH eliminated that problem entirely.

// The Problem SSH Solved

In the early days of networking, administrators used Telnet to remotely manage systems. Telnet worked, but it had a fatal flaw: it transmitted everything — commands, responses, and credentials — as unencrypted plain text. SSH replaced it with an encrypted tunnel using public-key cryptography, making any intercepted traffic useless. An attacker might capture the packets, but what they'd see is cipher gibberish with no way to decode it.

// What You Can Do Over SSH

Once connected, you have full shell access to the remote machine. In a penetration testing context this means: running reconnaissance commands, reading files and logs, checking for privilege escalation paths, installing or removing software, pivoting to other machines on the internal network, and executing anything you'd do if you were physically present — quietly and from anywhere in the world.

// Command Breakdown — Lab Example

# Connect to the Raspberry Pi discovered during the Nmap lab ssh student@192.168.1.100 # Breaking down each part: ssh → the SSH client program being called student → the username to log in as on the remote machine @ → separator between username and host address 192.168.1.100 → the IP address of the target (found via Nmap) The authenticity of host '192.168.1.100' can't be established. ED25519 key fingerprint is SHA256:aBcDeFgH1234... Are you sure you want to continue connecting (yes/no)? yes student@192.168.1.100's password: Linux raspberrypi 5.15.0 #1 SMP armv7l GNU/Linux student@raspberrypi:~$

In the grade-change lab, the workflow was: scan the network with Nmap to discover the Raspberry Pi → identify port 22 open (SSH) → connect with ssh student@<ip> → once inside, navigate to student record files and demonstrate what a real attacker could access. This chain is exactly what penetration testing is designed to expose — before someone with bad intent finds it first.

// Why Port 22?

Port 22 is the standard, well-known port for SSH. When Nmap shows port 22 as open on a host, it's a signal that SSH is running and accepting connections. A pentester will note this immediately — it means there's a remote access interface available. If credentials can be found or guessed, the entire machine is accessible. This is why default or weak SSH passwords represent a critical security risk.

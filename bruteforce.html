// 06 — CONCEPT

Brute-Force Attacks

Brute-force is an attack method, not a single tool. It describes the strategy of systematically trying every possible combination of credentials, characters, or keys until the correct one is found. It's the computational equivalent of trying every key on a keyring, one by one, until a door opens — except computers can try millions of keys per second.

// What Is a Brute-Force Attack?

A brute-force attack tries every possible combination within a defined character set — every letter, number, and symbol in every possible order and length. Given enough time and computing power, a brute-force attack against any password will eventually succeed. The limiting factor is time: an 8-character password using uppercase, lowercase, numbers, and symbols has over 200 trillion combinations. Even powerful hardware can take years. Brute-force is the most thorough method — and the slowest.

// Brute-Force vs. Dictionary Attack

Brute-Force: Every possible combination, starting from "a", then "b", working through "zzzzzzzzz" and every combination in between. Guaranteed to eventually find any password — given unlimited time.

Dictionary Attack: Uses a pre-built wordlist of known passwords, common words, leaked credentials, and predictable patterns instead of all possible combinations. It's a smarter, faster approach because most users choose passwords that already appear in wordlists — "password1", "qwerty", "iloveyou", "admin123". Hydra's use of rockyou.txt is a dictionary attack. In real engagements, dictionary attacks succeed far more often than pure brute-force because people are predictable.

// Penetration Test Scenario

During an authorized test, a tester identifies an SSH service with no account lockout policy. They run Hydra with the rockyou.txt wordlist against the admin account. Within four minutes, Hydra returns a valid credential. The tester logs in, confirms the access level, documents the finding, and includes it in the final report:

FINDING: Weak Credential + No Account Lockout Severity: CRITICAL Service: SSH (Port 22) Host: 192.168.1.50 Credential: admin / password1 Method: Dictionary attack (rockyou.txt) — succeeded in 4 minutes Access: Full shell access to production server RECOMMENDATIONS: 1. Immediately reset the 'admin' credential. 2. Enforce minimum 12-character passphrase policy. 3. Implement account lockout after 5 failed attempts. 4. Enable MFA for all SSH and privileged access. 5. Disable password authentication entirely — enforce SSH key pairs only.

⚠ ETHICS — THREE DEFENSES

1. Account Lockout: After a defined number of failed logins, the account is temporarily or permanently disabled. This turns a 4-minute dictionary attack into a years-long impossibility. Even locking for 30 seconds per failed attempt is enough to make automated attacks impractical.

2. Rate Limiting: Systems can detect abnormally high volumes of login requests and throttle or block the source IP. A human might make 5 attempts per minute. Hydra can make thousands. Rate limiting detects and kills that pattern automatically.

3. Multi-Factor Authentication (MFA): Even a perfectly cracked password becomes useless if the system requires a second factor — an authenticator app code, hardware key, or push notification. MFA doesn't stop a dictionary attack from guessing the password; it stops the attacker from actually using it.

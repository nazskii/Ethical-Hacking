Nmap — Network Mapper

Nmap is an open-source tool for network discovery and security auditing. It sends carefully crafted packets to hosts on a network and analyzes the responses to determine which systems are online, which ports are open, and what services — and versions of those services — are running on each one.

// What "Network Scanning" Actually Means

Before you can attack or defend a network, you need to know what's on it. Network scanning is the process of systematically probing a range of IP addresses to map out which hosts are alive and what they're running. Nmap automates this — a scan that would take hours manually can be done in seconds. The output gives a security tester a picture of the attack surface: every machine, every open port, every service that could be targeted or defended.

// What Are Ports?

A port is a numbered endpoint on a networked computer — think of it like a specific dock at a harbor where particular types of cargo arrive and depart. Port 22 handles SSH. Port 80 handles HTTP web traffic. Port 443 handles HTTPS. Port 3306 is MySQL databases. When a service is "running on a port," it's actively listening for connections on that number. To a security tester, an open port is a potential entry point. Knowing what's open — and exactly what version is running — is the starting point for almost every engagement.

// Real Nmap Command — With Explained Output

# Scan the entire subnet and detect service versions nmap -sV 192.168.1.0/24 -sV → version detection: identify software running on each open port 192.168.1.0/24 → CIDR notation: scan all 254 hosts on this subnet # Sample output: Nmap scan report for 192.168.1.100 PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 7.9p1 80/tcp open http Apache httpd 2.4.38 3306/tcp open mysql MySQL 5.7.36 8080/tcp open http-alt Werkzeug httpd 1.0.1 # PORT 22 — SSH is open: remote access interface available. # PORT 3306 — MySQL exposed on the LAN: database directly reachable. # PORT 8080 — Werkzeug: a Python dev server, almost never hardened. # All three are findings worth documenting in a pentest report.

Version detection (-sV) matters because knowing the exact version of a service lets a tester cross-reference it against known CVEs (Common Vulnerabilities and Exposures). An outdated version of OpenSSH might have a known exploit. An unpatched MySQL might have a privilege escalation path. The version number turns an open port into a specific, actionable finding.
